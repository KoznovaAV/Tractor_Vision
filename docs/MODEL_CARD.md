# Model Card — Tractor Vision Multi-Task Classifier

## Назначение

Одна сеть по фотографии техники предсказывает:

1. **Семью трактора** — один из 4 классов: `chtz`, `johndeere`, `kirovets`,
   `mtz_belarus`. Каждый класс охватывает всё семейство целиком (например,
   `kirovets` включает К-744, К-7М, К-525; `chtz` включает Б10М, Т-170, Т-130);
   модификации внутри семьи не различаются.
2. **Состояние** — `clean` или `dirty`.

Область применения: аудит парка техники по кадрам с камер (въезды в депо,
весовые, мойки), автоматический отсев техники, выезжающей грязной.

## Архитектура

- Backbone: **ConvNeXt-Tiny** (torchvision, предобучен на ImageNet), штатная
  голова заменена на `nn.Identity`.
- Две линейные головы над общим эмбеддингом 768: `model_head` (4), `state_head` (2).
- Вход: RGB `384×384`, нормализация по статистикам ImageNet.
- Подробности — `docs/ARCHITECTURE.md`.

## Обучение

- Partial fine-tuning: разморожена **1** последняя стадия backbone
  (`num_unfrozen_stages=1`), головы обучаются всегда.
- Дифференцированный LR: backbone учится в 10 раз медленнее голов (базовый LR `5e-4`).
- Балансировка потерь задач: **uncertainty weighting** (Kendall et al., 2018).
- `CrossEntropyLoss` с `label_smoothing=0.1`, оптимизатор `AdamW`
  (`weight_decay=1e-4`), `ReduceLROnPlateau` по `val_model_acc`, early stopping
  (`patience=15`).
- Данные: `data/dirty_clean` — синтетическая грязь (2 варианта на чистое фото)
  плюс реальные грязные фото в `train/<class>/dirty/` (префикс `real_`).
  См. `docs/DATA.md`.

## Метрики

Оценка на валидационном сплите `data/dirty_clean/val` (синтетическая грязь):

| Метрика | Значение |
|---------|----------|
| Accuracy семьи трактора (val) | **1.000** |
| Accuracy состояния clean/dirty (val) | **0.942** |

Оценка на held-out наборе **реальной** экстремальной грязи
(`data/real_dirty_val`, не участвует в обучении):

| Метрика | Значение | Цель |
|---------|----------|------|
| Dirty recall (реальная грязь) | **0.906** | ≥ 0.90 |

`val model accuracy = 1.000` достижимо из-за небольшого и визуально хорошо
разделимого набора классов; на новых доменах ожидается снижение.

## Версия чекпоинта

- Рабочий файл: `weights/multi_task_best.ckpt` (копия
  `weights/multi-task-best-epoch=13-val_model_acc=1.000.ckpt`).
- Формат: чекпоинт PyTorch Lightning; `state_dict` с префиксом `model.`,
  параметры балансировки (`log_var_*`) отбрасываются при загрузке.
- Гиперпараметры в чекпоинте: `num_unfrozen_stages=1`, `lr=5e-4`,
  `backbone_lr_factor=0.1`, `weight_decay=1e-4`, `loss_balancing=uncertainty`.
- Выбор чекпоинта в рантайме — `src/models/loader.py:resolve_working_checkpoint`
  (сначала `config.weights.multi_task`, иначе самый свежий по `mtime`
  `weights/multi-task-best-*.ckpt`).
- Метрику для `/models` API читает из метаданных чекпоинта, при отсутствии —
  из `config.yaml:fallback_accuracy`.

## Ограничения

- **4 семьи, без подмоделей**: `mtz_82` и `mtz_1221` слиты в `mtz_belarus`;
  модификации внутри семьи не различаются.
- **Домен обучения** — преимущественно веб-фото дневной съёмки. Ночь, сильная
  засветка, необычные ракурсы, частичные перекрытия ухудшают результат.
- **Состояние — бинарное и субъективное**: граница clean/dirty размыта; лёгкая
  пыль может классифицироваться как `clean`.
- **Синтетическая грязь ≠ реальная**: часть обобщения на реальный ил достигнута
  добавлением реальных фото и деградацией `mud_crust`; на грязи, не похожей на
  виденную, recall падает.
- Модель **не детектирует** трактор в кадре и не отклоняет фото без техники —
  на нерелевантном изображении вернёт уверенный, но бессмысленный класс.
- Датасет умеренного размера; возможна чувствительность к фону (цвет техники,
  типичное окружение семьи).

## Этика и риски

Ошибочная классификация состояния может привести к необоснованному
отстранению техники. Решения на основе модели должны допускать ручную
апелляцию. Модель не предназначена для идентификации людей или чтения номеров.
